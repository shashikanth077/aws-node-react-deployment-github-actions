2The application

LayerTechKey points
FrontendReact 19 + TypeScript + ViteFetches /api/products (same origin → no CORS). Loading, error + retry states. Card: image, name, price, description.
BackendNode 22 + ExpressGET /api/products, GET /health (liveness for ALB), GET /health/ready (checks DB). Env-var config, JSON logs, central error handler, graceful SIGTERM shutdown.
DatabaseMySQL 8 (RDS)products table, 5 seed rows, connection pool (mysql2, size 10/task, TLS with RDS CA bundle).
ImagesS3 (private)DB stores only the key (images/lamp.svg); API builds the URL from IMAGE_BASE_URL.
Why /health does not touch the database
If the ALB health check queried MySQL and the DB hiccupped, the ALB would mark both tasks unhealthy and take the whole site down. Liveness (/health) answers "is Node alive?"; readiness (/health/ready) answers "can it reach the DB?" and is for humans and debugging.

4Networking

Mental model in plain words

PieceThink of it as
VPCYour own private data centre inside AWS (10.0.0.0/16).
SubnetA room, pinned to one Availability Zone (a physically separate building).
Internet Gateway (IGW)The front door to the street. No IGW → no internet in or out.
Route tableSignposts: "to reach X, go through Y". A subnet is public only because its signpost says 0.0.0.0/0 → IGW.
NAT GatewayA one-way mail slot. Private tasks can send out (pull image, fetch secret) and get replies; strangers cannot start a conversation. Lives in a public subnet.
Security groupA firewall around each resource; stateful; rules can name another security group as the source.

Route tables

TableAttached toRoutes
product-public-rtpublic-a, public-b10.0.0.0/16 → local · 0.0.0.0/0 → IGW
product-private-rtprivate-app-a/b10.0.0.0/16 → local · 0.0.0.0/0 → NAT · S3 prefix list → gateway endpoint (free)
product-db-rtprivate-db-a/b10.0.0.0/16 → local only

Security groups — the chain

Why not expose 3000 or 3306? Port 3306 open to the world is how databases get scanned, brute-forced and ransomed within minutes — only Node needs MySQL, so only Node's SG may connect. Port 3000 open would let people bypass the load balancer (no health routing, no central logging/TLS/WAF); the tasks have no public IP anyway. One controlled front door: the ALB.

Create it (console)

VPC → Create VPC → "VPC and more": name product, 10.0.0.0/16, 2 AZs, 2 public + 2 private subnets with the CIDRs above, NAT gateways: In 1 AZ, VPC endpoint S3 Gateway, DNS hostnames on. Then add subnets private-db-a/b (10.0.5.0/24, 10.0.6.0/24) with a route table that has only the local route. Create alb-sg → ecs-sg → rds-sg in that order.

export VPC_ID=$(aws ec2 describe-vpcs --filters Name=tag:Name,Values=product-vpc --query 'Vpcs[0].VpcId' --output text)
aws ec2 describe-subnets --filters Name=vpc-id,Values=$VPC_ID \
  --query 'Subnets[].[Tags[?Key==`Name`]|[0].Value,AvailabilityZone,CidrBlock]' --output table
Pitfalls NAT placed in a private subnet · no 0.0.0.0/0 → NAT on the private table (tasks time out pulling images) · CIDR ranges instead of SG references · opening 3306 "temporarily" · DB subnets in one AZ · wrong console region.
Verify VPC → Resource map: public subnets → IGW route; private-app → NAT route; DB subnets → no 0.0.0.0/0; NAT is "Available" and in a public subnet. Stuck? Reachability Analyzer names the exact blocking rule.

How Node gets the password — two IAM roles

RoleUsed byForPermissions
Task execution role
productApiTaskExecutionRole		The ECS agent, before your code startsPull image from ECR, write log streamsAWS-managed AmazonECSTaskExecutionRolePolicy
Task role
productApiTaskRole		Your Node code, while runningAny AWS API the app callsInline: secretsmanager:GetSecretValue on this one secret ARN
Why not inject it as an ECS "secret" env var? You can ("secrets":[{"name":"DB_PASSWORD","valueFrom":"<arn>:password::"}], needs the execution role to read it). But it is read once at task start, and RDS-managed secrets rotate every 7 days — running tasks would keep a stale password. Reading it in code with the task role self-heals and teaches the pattern you will reuse for S3/SQS.
aws iam create-role --role-name productApiTaskExecutionRole --assume-role-policy-document file://infra/ecs-tasks-trust-policy.json
aws iam attach-role-policy --role-name productApiTaskExecutionRole --policy-arn arn:aws:iam::aws:policy/service-role/AmazonECSTaskExecutionRolePolicy
aws iam create-role --role-name productApiTaskRole --assume-role-policy-document file://infra/ecs-tasks-trust-policy.json
bash scripts/render-task-role-policy.sh > infra/task-role-policy.rendered.json
aws iam put-role-policy --role-name productApiTaskRole --policy-name read-db-secret --policy-document file://infra/task-role-policy.rendered.json
Pitfalls Public access = Yes · forgetting the initial DB name (Unknown database) · secretsmanager:* on * · password in environment · no NAT/endpoint, so Secrets Manager is unreachable · fixing the wrong role (error from Node → task role; task fails to start → execution role).

6S3 — images and the React build

What: object storage; a file is addressed by a key such as images/headphones.svg. Why: images do not belong in MySQL (bloat, slow) or in the Docker image (every picture change would need a redeploy). The row stores the key; S3 stores the bytes; browsers fetch them via CloudFront so Node never serves an image.

aws s3api create-bucket --bucket "$BUCKET" --region "$AWS_REGION" --create-bucket-configuration LocationConstraint="$AWS_REGION"
aws s3api put-public-access-block --bucket "$BUCKET" --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
aws s3 sync assets/images "s3://$BUCKET/images" --cache-control "public, max-age=86400"
aws s3 presign "s3://$BUCKET/images/headphones.svg" --expires-in 300     # opens the picture; plain URL → AccessDenied (correct!)
Pitfalls turning off Block Public Access "to make it work" · key mismatch between DB and S3 (case-sensitive, no leading "/") · very long cache on files you later overwrite · S3 returns 403 (not 404) for missing keys when you lack ListBucket.

Fargate = "run this container with 0.25 vCPU and 512 MB"; AWS finds the compute. No servers to patch. Each task gets its own network interface (private IP + security group) in awsvpc mode.

aws ecs create-cluster --cluster-name product-cluster
export IMAGE_URI=$ECR_URI:1.0.0 && bash scripts/render-task-def.sh
aws ecs register-task-definition --cli-input-json file://infra/task-definition.rendered.json

# one-off task: same image, different command → creates the table + 5 products
aws ecs run-task --cluster product-cluster --launch-type FARGATE --task-definition product-api \
  --network-configuration "awsvpcConfiguration={subnets=[$PRIV_A],securityGroups=[$ECS_SG],assignPublicIp=DISABLED}" \
  --overrides '{"containerOverrides":[{"name":"product-api","command":["node","src/scripts/init-db.js"]}]}'
aws logs tail /ecs/product-api --follow --since 5m      # expect: db_credentials_loaded … db_seeded

Create the service (2 tasks, 2 AZs) — after the ALB exists (next chapter)

aws ecs create-service --cluster product-cluster --service-name product-api-service \
  --task-definition product-api --desired-count 2 --launch-type FARGATE \
  --network-configuration "awsvpcConfiguration={subnets=[$PRIV_A,$PRIV_B],securityGroups=[$ECS_SG],assignPublicIp=DISABLED}" \
  --load-balancers "targetGroupArn=$TG_ARN,containerName=product-api,containerPort=3000" \
  --health-check-grace-period-seconds 30 \
  --deployment-configuration "deploymentCircuitBreaker={enable=true,rollback=true},minimumHealthyPercent=100,maximumPercent=200"

Zero-downtime rolling deployment

# deploy a new version
docker build -t product-api:1.0.1 backend && docker tag product-api:1.0.1 $ECR_URI:1.0.1 && docker push $ECR_URI:1.0.1
export IMAGE_URI=$ECR_URI:1.0.1 && bash scripts/render-task-def.sh
aws ecs register-task-definition --cli-input-json file://infra/task-definition.rendered.json
aws ecs update-service --cluster product-cluster --service product-api-service --task-definition product-api

9Application Load Balancer

What: the single front door that accepts HTTP(S), picks a healthy task and forwards the request. Why: task IPs change constantly and there are two; the ALB gives one stable DNS name, balances across AZs and stops sending traffic to failing tasks.

Target group fieldValue
Target typeIP (required for Fargate) · name product-api-tg · HTTP : 3000
Health checkpath /health · interval 15 s · timeout 5 s · healthy 2 · unhealthy 3 · success 200
Attributederegistration delay 30 s (default 300 s makes each deploy 5 min slower)

Load balancer: Internet-facing, IPv4, VPC product-vpc, subnets public-a + public-b, security group alb-sg only, listener HTTP:80 → product-api-tg.

Verify high availability

aws elbv2 describe-target-health --target-group-arn $TG_ARN --query 'TargetHealthDescriptions[].[Target.Id,TargetHealth.State]' --output table
curl -s http://$ALB_DNS/api/products | head -c 300
TASK=$(aws ecs list-tasks --cluster product-cluster --service-name product-api-service --query 'taskArns[0]' --output text)
aws ecs stop-task --cluster product-cluster --task $TASK --reason "HA test"
for i in $(seq 1 20); do curl -s -o /dev/null -w "%{http_code} " http://$ALB_DNS/health; sleep 2; done   # 200 200 200 …

10CloudFront and the React frontend

Why CloudFront: (1) free HTTPS on *.cloudfront.net — an ALB :443 listener needs a domain + certificate; (2) one origin for everything, so no CORS and no mixed-content errors; (3) the S3 bucket stays private.

cd frontend && npm ci && npm run build && cd ..
aws s3 sync frontend/dist "s3://$BUCKET" --delete --exclude "images/*" --exclude "index.html" --cache-control "public, max-age=31536000, immutable"
aws s3 cp frontend/dist/index.html "s3://$BUCKET/index.html" --cache-control "no-cache"

Hashed JS/CSS (index-YEUI1bVh.js) can be cached for a year; index.html must always be re-checked.

Create in the consoleSettings

11CloudWatch — logs, metrics, alarms

Containers are disposable and have no SSH; if it is not in CloudWatch, it is gone when the task dies. Our logger prints one JSON object per line with console.log; Docker captures stdout; the awslogs driver (in the task definition) forwards it. No agent, no code changes.

Find your console.log output

Console: CloudWatch → Logs → Log groups → /ecs/product-api → pick a stream (two tasks = two streams) or Search all log streams. CLI:

aws logs tail /ecs/product-api --follow --since 10m
aws logs tail /ecs/product-api --since 1h --filter-pattern '"level":"error"'
# sample line:
{"time":"…","level":"info","msg":"request","requestId":"Root=1-67…","method":"GET","path":"/api/products","status":200,"ms":6.4}

Logs Insights queries (JSON fields are discovered automatically)

fields @timestamp, msg, err.message, requestId | filter level = "error" | sort @timestamp desc | limit 50
filter msg = "request" | stats count() as n, avg(ms), pct(ms,95) as p95 by bin(5m)
filter msg = "request" and status >= 500 | stats count() by path

Pitfalls no retention (never-expiring logs cost money) · logging secrets/bodies · unstructured logs you cannot filter · alarm without a confirmed SNS subscription · wrong region/time range in the console.

What this run proved about the design Image pull through the NAT, the task role reading the secret, TLS to RDS with the CA bundle baked into the image, the ALB health check that ignores the DB, graceful 2-AZ failover, and path-based routing in CloudFront — all worked on the first attempt with the files in this repository. The only failures were Windows tooling quirks, not AWS design.

One-page runbook (reproduce or redeploy)

# 0  once per terminal (Git Bash)
export MSYS_NO_PATHCONV=1 AWS_REGION=eu-north-1 AWS_DEFAULT_REGION=eu-north-1 && source infra/.deployed.env
# 1  ship a new backend version
docker build -t product-api:1.0.1 backend && docker tag product-api:1.0.1 $ECR_URI:1.0.1
#    push with the throw-away docker config (see chapter 14, problem 1), then:
export IMAGE_URI=$ECR_URI:1.0.1 && bash scripts/render-task-def.sh
aws ecs register-task-definition --cli-input-json file://infra/task-definition.rendered.json
aws ecs update-service --cluster product-cluster --service product-api-service --task-definition product-api
aws ecs wait services-stable --cluster product-cluster --services product-api-service
# 2  ship a new frontend
npm --prefix frontend run build
aws s3 sync frontend/dist s3://$BUCKET --delete --exclude "images/*" --exclude "index.html" --cache-control "public, max-age=31536000, immutable"
aws s3 cp frontend/dist/index.html s3://$BUCKET/index.html --cache-control no-cache
aws cloudfront create-invalidation --distribution-id $CF_ID --paths "/index.html"
# 3  look at it
aws logs tail /ecs/product-api --follow --since 10m
curl -s https://$CF_DOMAIN/api/products | head -c 300

Cost status and teardown for this exact stack

Running now The stack is live and billing roughly $2–3 per day (NAT Gateway, 2 Fargate tasks, ALB, public IPv4, RDS beyond any free allowance). No budget or CloudWatch/SNS alarms were created. To stop the bill, delete in the order below (all IDs come from infra/.deployed.env).
source infra/.deployed.env
aws cloudfront get-distribution-config --id $CF_ID # → set Enabled=false, update-distribution with the ETag, wait Deployed, then delete-distribution
aws ecs update-service --cluster product-cluster --service product-api-service --desired-count 0
aws ecs delete-service --cluster product-cluster --service product-api-service --force
aws ecs delete-cluster --cluster product-cluster
aws elbv2 delete-load-balancer --load-balancer-arn $ALB_ARN          # wait ~1 min
aws elbv2 delete-target-group --target-group-arn $TG_ARN

aws rds delete-db-subnet-group --db-subnet-group-name product-db-subnet-group
